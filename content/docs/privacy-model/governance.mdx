# Protocol Governance

Herald is currently in Phase 1 (Centralized Gateway). Our long-term goal is to transition the entire notification infrastructure into a decentralized, permissionless protocol.

## Phase 1: Managed Infrastructure (Current)
Herald operates the Notification Gateway and Secure Enclaves. Governance is handled by the core team with input from early protocol partners.

## Phase 2: Registry Decentralization
The Identity Registry is already on Solana. In Phase 2, we will introduce on-chain voting for category definitions, global rate limits, and protocol whitelist management.

## Phase 3: Distributed Gateway Network
We aim to allow third parties to run their own "Herald Nodes" using Trusted Execution Environments (TEEs). Users will be able to choose which gateway they trust with their encrypted data.

---

## Tokenomics (Future)
The $HERALD token will be used for:
- **Staking**: Node operators must stake tokens to participate in the delivery network.
- **Voting**: Token holders can vote on protocol parameters and fee structures.
- **Discounts**: Staking tokens will provide protocols with discounted messaging quotas.
